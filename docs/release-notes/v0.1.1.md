# dtDynamics 0.1.1

Author: Joonhee Jo
Date: 2026-07-28

## 결과

0.1.1은 외부 XML과 editable model이 realtime에 들어가기 전에 실패하도록 setup contract를 강화했다. production compute API와 `dtMath`-only 경계는 유지하고, checked validation, typed XML diagnostic, name lookup symmetry, zero-DoF support, installed package identity를 추가했다.

이 릴리스는 최종 검증과 독립 검토를 통과한 패키지 결과를 기록하며, 명시적 승인에 따라 게시한다.

## Package identity

- CMake package version: `0.1.1`
- exported target: `dt::Dynamics`
- canonical prefix: `${ARTF_INSTALL_DIR:-$HOME/.local/ART_Framework}`
- `find_package(dtDynamics 0.1.1 EXACT CONFIG REQUIRED)` consumer 검증
- source/isolated/canonical public-header version: `0.1.1`

## Setup validation

새 public API:

- `ValidateSpec`
- `ValidateModel`
- `CompileSpecChecked`
- `dtDynValidationCode`
- `dtDynValidationError`

invalid parent/owner/reference, detached object, topology cycle, duplicate name, unsupported joint, dimension overflow, non-finite physical value를 setup에서 fail-closed 처리한다. 기존 `CompileSpec`는 trusted setup path의 backward compatibility를 위해 유지한다.

## XML diagnostic

`dtDynXmlError`는 stable `Code()`, exact `SourcePath()`, zero-based original-input `Offset()`을 제공한다. malformed markup, invalid/overflow number, `NaN`/`Inf`, wrong vector arity, duplicate names, unresolved references, unsupported syntax·semantics를 명시적으로 거부한다. XML declaration은 byte 0에서 한 번만 허용한다.

Filesystem은 `LoadXmlFile`/`SaveXmlFile`, memory text는 `DecodeXml`/`EncodeXml`을 사용한다. generic caller-side text reader는 package workflow가 아니다.

## Lookup과 fixed model

`dtDynSpec`와 `dtDynModel`은 `BodyId`, `JointId`, `SiteId`, `ActuatorId`의 body, joint, site, actuator lookup을 모두 제공한다. mutable spec은 linear scan, compiled model은 rebuilt map을 사용하며 missing name은 `DTDYN_INVALID_INDEX`다.

`nq == 0`, `nv == 0`인 fully fixed model의 `dtDynData::Resize()`를 지원한다. site Jacobian의 logical shape은 `3 x 0`, dynamics matrix는 `0 x 0`으로 유지된다.

## Benchmark와 reference

fixture coverage는 branching fixed-base, multi-root floating-base, mixed fixed/jointed, 10/30-DOF serial chain을 포함한다. raw/normalized CSV는 median, p95, p99와 seven-batch summary를 제공하며 figure source CSV를 함께 설치한다.

MuJoCo 3.8.0과 Pinocchio 3.9.0 timing은 identical-output speed ratio가 아니라 contextual external-library overhead다. numerical comparison은 equivalent quantity만 `ok`로 인정하고 non-equivalent centroidal rows는 `skipped` diagnostic으로 남긴다. non-finite error/tolerance와 missing/duplicate summary coverage는 validator가 거부한다.

채택된 benchmark 조건은 Release, GCC 11.4.0, Intel Xeon w7-3545, CPU 0 affinity, `powersave` governor, batch 7회, batch별 warmup 20회와 measurement 200회다. frequency lock, realtime priority, hard deadline은 적용하지 않았다.

## Validation gate

릴리스에서 실행한 핵심 gate:

```bash
cmake --preset validation
cmake --build --preset validation -- -j2
ctest --preset validation --output-on-failure
python3 tools/validate_reference_benchmark.py \
  --references /tmp/references.csv \
  --runtime-csv docs/figures/runtime_by_fixture.csv
tools/validate_package.sh --skip-benchmarks
tools/validate_docs.sh
```

native/MuJoCo/Pinocchio CTest는 3/3 통과했다. install/export gate는 exact version, public validation/compile API, zero-DoF resize, lookup sentinel과 함께 inline `DecodeXml` 및 filesystem `LoadXmlFile` consumer를 installed headers/library로 각각 compile·link·run했다.

## Compatibility와 제한

- strict XML/checked validation은 이전 silent acceptance를 거부할 수 있다.
- `IsCompatible`은 storage dimension-only이며 exact model identity가 아니다.
- neutral/default state initializer는 NO-GO다.
- stage median은 독립 측정이며 additive decomposition이 아니다.
- allocation 0은 benchmark의 C++ `operator new` counter 범위에 한정된다.
- closed-chain constraints, contact, simulation, controller policy는 scope 밖이다.

과거 `v0.1.0-rc1`~`rc3` note는 당시 evidence를 보존하며 0.1.1 결과로 소급하지 않는다.
