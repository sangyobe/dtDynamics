# dtDynamics 0.1.1

Author: Joonhee Jo
Date: 2026-07-28

## 결과

- 0.1.1 핵심 변경: 외부 XML과 editable model이 realtime에 들어가기 전에 실패하도록 setup contract 강화
- 유지 사항: production compute API, `dtMath`-only 경계
- 추가 사항: checked validation, typed XML diagnostic, name lookup symmetry, zero-DoF support, installed package identity

- 이 릴리스 기록 대상: 최종 검증과 독립 검토를 통과한 패키지 결과
- 게시 조건: 명시적 승인

## Package identity

- CMake package version: `0.1.1`
- exported target: `dt::Dynamics`
- canonical prefix: `${ARTF_INSTALL_DIR:-$HOME/.local/ART_Framework}`
- `find_package(dtDynamics 0.1.1 EXACT CONFIG REQUIRED)` consumer 검증
- source/isolated/canonical public-header version: `0.1.1`

## Setup validation

- 새 public API:
  - `ValidateSpec`
  - `ValidateModel`
  - `CompileSpecChecked`
  - `dtDynValidationCode`
  - `dtDynValidationError`

- setup에서 fail-closed 처리하는 항목: invalid parent/owner/reference, detached object, topology cycle, duplicate name, unsupported joint, dimension overflow, non-finite physical value
- 기존 `CompileSpec` 유지 목적: trusted setup path의 backward compatibility

## XML diagnostic

- `dtDynXmlError` 제공 항목: stable `Code()`, exact `SourcePath()`, zero-based original-input `Offset()`
- 명시적 거부 대상: malformed markup, invalid/overflow number, `NaN`/`Inf`, wrong vector arity, duplicate name, unresolved reference, unsupported syntax·semantics
- XML declaration 허용 조건: byte 0에서 한 번만

- Filesystem 처리: `LoadXmlFile`/`SaveXmlFile`
- memory text 처리: `DecodeXml`/`EncodeXml`
- 원칙: generic caller-side text reader는 package workflow 아님

## Lookup과 fixed model

- `dtDynSpec`와 `dtDynModel` 공통 제공: `BodyId`, `JointId`, `SiteId`, `ActuatorId`의 body, joint, site, actuator lookup
- lookup 방식: mutable spec은 linear scan, compiled model은 rebuilt map
- missing name 반환값: `DTDYN_INVALID_INDEX`

- 지원 대상: `nq == 0`, `nv == 0`인 fully fixed model의 `dtDynData::Resize()`
- 이때 유지되는 shape: site Jacobian은 `3 x 0`, dynamics matrix는 `0 x 0`

## Benchmark와 reference

- fixture coverage: branching fixed-base, multi-root floating-base, mixed fixed/jointed, 10/30-DOF serial chain
- raw/normalized CSV 제공 항목: median, p95, p99, seven-batch summary, figure source CSV

- MuJoCo 3.8.0, Pinocchio 3.9.0 timing 성격: identical-output speed ratio가 아닌 contextual external-library overhead
- numerical comparison 원칙: equivalent quantity만 `ok`로 인정, non-equivalent centroidal row는 `skipped` diagnostic으로 기록
- validator 거부 대상: non-finite error/tolerance, missing/duplicate summary coverage

- 채택된 benchmark 조건: Release, GCC 11.4.0, Intel Xeon w7-3545, CPU 0 affinity, `powersave` governor, batch 7회, batch별 warmup 20회와 measurement 200회
- 미적용 항목: frequency lock, realtime priority, hard deadline

## Validation gate

- 릴리스에서 실행한 핵심 gate:

```bash
cmake --preset validation
cmake --build --preset validation -- -j2
ctest --preset validation --output-on-failure
python3 tools/validate_reference_benchmark.py \
  --references /tmp/references.csv \
  --runtime-csv docs/figures/runtime_by_fixture.csv
tools/validate_package.sh --skip-benchmarks
python3 tools/validate_docs.py
```

- native/MuJoCo/Pinocchio CTest 결과: 3/3 통과
- install/export gate 검증 내용: exact version, public validation/compile API, zero-DoF resize, lookup sentinel과 함께 inline `DecodeXml` 및 filesystem `LoadXmlFile` consumer를 installed headers/library로 각각 compile·link·run

## Compatibility와 제한

- strict XML/checked validation 영향: 이전 silent acceptance를 거부할 수 있음
- `IsCompatible` 범위: storage dimension-only (exact model identity 아님)
- neutral/default state initializer: NO-GO
- stage median 성격: 독립 측정 (additive decomposition 아님)
- allocation 0 범위: benchmark의 C++ `operator new` counter 범위에 한정
- 미포함 항목: closed-chain constraint, contact, simulation, controller policy

- 과거 `v0.1.0-rc1`~`rc3` note: 당시 evidence 보존 (0.1.1 결과로 소급하지 않음)
