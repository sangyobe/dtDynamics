# dtDynamics v0.1.0-rc3 Release Candidate

Date: 2026-07-16

## Identity

- Package version: `0.1.0`
- Tag: `v0.1.0-rc3`
- Commit: tagged commit

## Why rc3

`v0.1.0-rc3` keeps the corrected direct `${ARTF_INSTALL_DIR}` installation contract from rc2 and adds a publishable package manual, generated Doxygen/Graphviz documentation, expanded benchmark/resource inspection, and clearer realtime-allocation scope.

Publication-specific manuscript, review, and large evidence materials are maintained separately. This release remains focused on package source, API documentation, validation, and reusable benchmark tooling.

## Scope

This candidate includes:

- Public namespace and CMake target: `dt::Dynamics`.
- Production dependency boundary: `dtMath` only.
- Doxygen manual pages covering model/spec/data layers, computation, integration, realtime use, validation, limitations, examples, benchmarks, and release workflow.
- MuJoCo-style public `dtDynModel`/`dtDynData` field comments with dimensions, indexing, frame, and stacked-root semantics.
- Graphviz diagrams and responsive benchmark figures.
- Native, stage, MuJoCo, and Pinocchio validation/benchmark paths.
- Setup/off-loop resource inspection rows for `CompileSpec(spec)` and fresh `dtDynData::Resize(model)`.
- Raw CSV allocation counters retained for regression checking while all-zero columns are omitted from human-facing timing tables.
- Local development-tool and Python-cache ignore rules for clean source archives.

## Installation

```bash
cmake --preset release
cmake --build --preset release -- -j2
cmake --install build/release --prefix "${ARTF_INSTALL_DIR:-$HOME/.local/ART_Framework}"
```

Consumers should use `find_package(dtDynamics CONFIG REQUIRED)` and link `dt::Dynamics`.

## Validation Gate

Before tagging rc3, run:

```bash
tools/audit_release_readiness.sh
tools/validate_docs.sh
cmake --preset native-validation
cmake --build --preset native-validation -- -j2
ctest --preset native-validation
```

Optional downstream integrations should maintain their own installed-package gate. A complete gate should confirm the direct ART Framework prefix, reject stale isolated-prefix selection, build against `find_package(dtDynamics CONFIG REQUIRED)`, and run the downstream headless validation sequence. The standalone dtDynamics archive does not ship downstream-repository validation scripts.

## Release Packaging

From a clean committed tree:

```bash
tools/package_release.sh --version v0.1.0-rc3 --output-dir dist
```

The archive and checksum must be generated from the exact commit to be tagged.

## Known Limits

- Setup/resource timings are inspection evidence, not controller-loop timing.
- C++ allocation counters are diagnostics, not complete malloc-family or OS heap traces.
- p99 values remain scheduling/frequency-sensitive; the current report uses fixed CPU affinity and seven-batch summaries but not frequency locking or realtime priority.
- Validation-only Pinocchio/Boost warnings may originate from the private dependency prefix; they are not production dependencies.
- Publication-specific manuscript materials are maintained separately and are not part of this candidate.
