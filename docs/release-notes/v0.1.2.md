# dtDynamics 0.1.2

Author: Joonhee Jo
Date: 2026-09-16

## 결과

- `dtDynSpec`의 public mutable collection accessor를 제거하고 immutable collection view와 callback-scoped `EditBody`/`EditJoint`/`EditSite`/`EditActuator` transaction으로 전환
- edit callback은 draft copy에만 쓰며, 정상 반환 때만 commit
- nested `Edit*`, `Add*`, `Clear`, assignment, ADL `swap` reentrancy는 active transaction을 abort. inner `std::logic_error`를 callback에서 잡아도 outer edit는 commit하지 않음
- production source의 Polyspace Bug Finder 및 선택된 MISRA C++:2023 rule subset에서 raw defect 0 정책 적용

## Encapsulation과 setup contract

- 읽기: `Bodies()`, `Joints()`, `Sites()`, `Actuators()`는 const view만 반환
- 수정: item ID를 지정한 `Edit*` callback 안에서만 draft item을 수정
- 실패: invalid ID는 `std::out_of_range`; callback 예외 또는 reentrancy abort는 stored item을 변경하지 않고 전파
- semantic guard: committed edit도 external setup input으로 취급하므로 `ValidateSpec()` 및 `CompileSpecChecked()`를 거쳐야 함
- runtime 영향: collection edit, validation, compilation, `dtDynData::Resize()`는 control tick 밖에서만 수행

## Compatibility와 migration

- source compatibility change: 이전 `spec.Bodies()[id].field = value` 형태는 더 이상 compile되지 않음
- migration: `spec.EditBody(id, [](dtDynBodySpec &draft) { draft.field = value; });` 형태를 사용
- `dtDynModel`, `dtDynData`, compute API와 `dtMath`-only production dependency 경계는 유지
- source-level migration 뒤에도 `ValidateSpec()`/`CompileSpecChecked()`로 topology/physical-data validity를 확인
