# dtDynamics v0.1.3

Author: Joonhee Jo
Date: 2026-10-21

## 결과

- `UpdateSpec(const dtDynSpec&, dtDynModel&)`를 추가했다. fixed-layout compiled model에서 body/joint/site/actuator의 physical parameter와 derived cache를 갱신한다.
- `CompileSpec()`은 topology/layout/storage/name-map 준비를 담당하고, physical parameter replay는 `UpdateSpec()`으로 분리했다.
- compatibility preflight는 body hierarchy, joint owner/type/address, site ownership, actuator/root mapping, `jnt_specid` provenance를 확인한다. 구조가 다르면 model을 쓰지 않고 `false`를 반환한다.
- `dtArray::push_back`의 upstream value-category regression을 수정했다. lvalue alias, self-rvalue transfer, move-only element, deleted assignment 조합을 regression으로 고정했다.

## Compatibility와 realtime 경계

- `UpdateSpec()`은 fixed-layout physical update 전용이다. body/joint/site/actuator 수, hierarchy, joint type/address, root·actuator mapping, name을 바꾸는 입력은 새 model compile 경로로 처리한다.
- 성공 update 뒤 기존 `dtDynData` kinematics/dynamics output은 stale이다. 소비 전에 `ForwardKinematics` 또는 필요한 `ComputeDynamics*()`를 다시 실행한다.
- successful update의 counted C++ `operator new`/`operator new[]` 증가는 regression에서 허용하지 않는다. 다만 target CPU worst-case time과 controller deadline은 별도 측정 대상이다.

## v0.1.3 tag 이후 변경

- 이 절은 `v0.1.3` tag(`f9fcea8`) 이후 `main`에 반영하는 변경이며 tag의 내용을 바꾸지 않는다.
- `tools/package_release.sh`: 아카이브 커밋 ID 확인에서 `gzip -dc | git get-tar-commit-id` 파이프를 임시 파일 방식으로 바꿨다. `git get-tar-commit-id`가 tar 헤더만 읽고 종료하면 아직 압축을 풀고 있던 `gzip`이 SIGPIPE(141)로 죽고, `set -o pipefail` 때문에 아카이브가 64 KiB보다 크면 스크립트가 중단되었다. `v0.1.3` 아카이브는 같은 검증을 수동으로 수행해 만들었으며, 수정한 스크립트로 다시 만든 아카이브와 바이트 단위로 같다.
- `tools/test_package_release_contract.py`: 64 KiB를 넘는 아카이브 회귀와, 아카이브 커밋 ID가 tag 커밋과 다를 때 거부하는 회귀를 추가했다. 기존 테스트는 아카이브가 작아 SIGPIPE를 재현하지 못했다.
- CI 계약 테스트(`tools/test_gitlab_ci_contract.py`, `tools/test_gitlab_ci_contract_parser.py`)와 `ci/lint.sh`의 package-config include 순서 검사를 추가했다. 기존 MR !7의 내용이며 `tools/test_ci_lint.py`가 이 호출을 검증한다.
